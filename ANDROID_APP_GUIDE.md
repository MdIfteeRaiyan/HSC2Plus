# HSC2Plus Android launch guide

Recommended first release: **Progressive Web App + Trusted Web Activity (TWA)**. HSC2Plus is primarily a responsive web application, so TWA keeps one codebase, preserves the website experience and produces an Android App Bundle for Google Play.

## Phase 1 — confirm the live PWA

1. Push this release to GitHub and allow Vercel to deploy it.
2. Open the final HTTPS domain on Android Chrome.
3. Confirm these URLs return `200`:
   - `https://YOUR_DOMAIN/manifest.webmanifest`
   - `https://YOUR_DOMAIN/manifest.webmanifest`
   - `https://YOUR_DOMAIN/icon-192.png`
   - `https://YOUR_DOMAIN/icon-512.png`
4. In Chrome, use **Add to Home screen / Install app**.
5. Test launch, navigation, notes, practice, Test Centre, offline fallback and progress restore on a real Android device.

This installable PWA can be released to students before Play Store publication.

## Phase 2 — create the Android wrapper

Use a permanent package name; changing it later creates a different app. Suggested package:

```text
com.hsc2plus.app
```

Install current Node.js and Java, then install Bubblewrap:

```bash
npm install -g @bubblewrap/cli
bubblewrap init --manifest=https://YOUR_DOMAIN/manifest.webmanifest
```

During setup:

- App name: `HSC2Plus`
- Launcher name: `HSC2Plus`
- Package ID: `com.hsc2plus.app`
- Start URL: `/`
- Display mode: `standalone`
- Theme colour: `#0a6b5c`
- Background colour: `#f4f8f6`
- Signing key: create a new upload key and keep its file/password securely backed up

Build the Android project:

```bash
bubblewrap build
```

Keep the generated Android wrapper in a separate repository or an `android/` folder. Never commit the keystore, signing passwords, `.env` files or Play credentials.

## Phase 3 — connect the app and website

The app initially opens as a Custom Tab until Digital Asset Links verifies that the website and Android package belong to the same owner.

1. Obtain the SHA-256 certificate fingerprint. For the final Play build, use the **Play App Signing certificate** fingerprint from Play Console—not only the local upload-key fingerprint.
2. Create this public file on the website:

```text
public/.well-known/assetlinks.json
```

3. Use this structure, replacing the fingerprint:

```json
[
  {
    "relation": ["delegate_permission/common.handle_all_urls"],
    "target": {
      "namespace": "android_app",
      "package_name": "com.hsc2plus.app",
      "sha256_cert_fingerprints": ["YOUR:PLAY:SIGNING:SHA256:FINGERPRINT"]
    }
  }
]
```

4. Deploy again and confirm `https://YOUR_DOMAIN/.well-known/assetlinks.json` returns HTTP `200` with JSON content.
5. Reinstall the test build and confirm it opens full-screen without browser controls.

## Phase 4 — test before Play Store submission

Test at minimum:

- Android 10, 12 and a current Android version
- Low-end phone and slow network
- First install, upgrade and uninstall/reinstall
- Online and offline launch
- Back button and deep links
- Commerce/Humanities switching
- Bangla font rendering and 200% text scaling
- MCQ, CQ, model test, timer expiry and refresh recovery
- PDF view/download/upload
- Audio start/stop and interruption by phone calls
- Login, logout and local-to-cloud progress restoration if Supabase is enabled
- Service-worker update after deploying a new website version

Use Play Console **Internal testing** first, then **Closed testing** with teachers and students. Fix blockers before production rollout.

## Phase 5 — Google Play release

1. Create the app in Play Console using the exact package ID.
2. Complete developer verification and app details.
3. Enrol in Play App Signing.
4. Upload the signed `.aab` generated by the Android build.
5. Provide app icon, feature graphic, phone/tablet screenshots and a short/long description.
6. Complete Data safety, privacy-policy URL, content rating, target audience, ads and app-access declarations truthfully.
7. Publish to Internal testing.
8. Add testers, install from the Play testing link and complete the real-device checklist.
9. Promote to Closed testing, then Production only after the academic-review and beta blockers are acceptable.

For every later website-only update, Vercel deployment updates the TWA content automatically. A new Play bundle is needed when Android wrapper settings, package permissions, icons, signing configuration or native behavior changes.
